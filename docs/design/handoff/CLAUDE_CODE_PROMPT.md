# Промт для Claude Code: редизайн и доработка IPTV

Скопируйте всё ниже линии в Claude Code, запущенный в корне репозитория `volnalabs/IPTV`.
Перед запуском положите этот пакет в репозиторий как `docs/design/handoff/` (вместе с папками `tokens/`, `icons/`, `fonts/`, `screens/`, `flows/`, `design-system/`, `reference/`).

---

Ты — ведущий разработчик проекта IPTV (этот репозиторий). Задача — реализовать утверждённый редизайн интерфейса «Тихий эфир» и согласованные доработки на всех платформах: Android TV, Android (телефон и планшет), Samsung Tizen, LG webOS, Desktop (Electron).

## Источник истины

1. `docs/design/handoff/SPEC.md` — полная спецификация: карта экранов, токены, компоненты с размерами и состояниями, активный плеер, настройки, плагины, платформы, поведение пульта, клавиатуры, мыши и касаний, ресурсы, технические ограничения, чек-лист приёмки. Прочитай её целиком до начала работы.
2. `docs/design/handoff/screens/*.jpg` — эталонные макеты (ТВ — холст 1920×1080, Desktop — 1440×900 / 1280×800 / 1920×1080, телефон — 360/390/430 по ширине). `TV-Guide.jpg` — главный экран.
3. `docs/design/handoff/flows/*.jpg` — кадры сценариев из прототипа (`tv-*` — пульт, `desk-*` — мышь и клавиатура, `phone-*` — касания).
4. `docs/design/handoff/tokens/` — `tokens.json` (основной), `tokens.extra.json` (дополнения), `android/colors.xml`, `android/dimens.xml`.
5. `docs/design/handoff/icons/` — 48 SVG и `icons.json` (имя → `d`). `fonts/` — Onest WOFF2 + WOFF и `onest.css`.
6. `docs/design/handoff/reference/screens.css` и `ds-components.css` — CSS макетов. Это **справка по размерам и цветам**, не код для копирования: там есть `var()` и `gap`, которые на старых ТВ не работают.
7. `docs/design/handoff/design-system/*.md` — правила дизайн-системы.

Если SPEC и макет расходятся, прав SPEC. Если SPEC расходится с реальным кодом (функции нет, API другой), не выдумывай: сделай ближайшее честное решение и запиши его в `docs/design/DEVIATIONS.md` (что, где, почему).

## Жёсткие ограничения

- **Архитектуру не меняем.** Android — Kotlin + Android Views + Media3 в `app/`. Samsung, LG и Desktop — общий web-интерфейс в `web/` (один `app.js`, `style.css`, `index.html`), Electron в `desktop/`. Без React/Compose/фреймворков, новых сборщиков и серверных API.
- **`web/` — строго ES5**: `var`, `function`; без стрелочных функций, `let/const`, шаблонных строк, `class`, `async`, `Object.assign`, `Array.from`, `includes`. `Promise` и `fetch` — только с проверкой наличия, как сейчас.
- **CSS в `web/style.css`**: без `var()`, grid, `gap` у flex, `backdrop-filter`, `aspect-ratio`, `inset`, `sticky`, `clamp/min/max`, `:focus-visible` (вместо него класс), `text-decoration-thickness`/`text-underline-offset`. Свойства transform/transition/animation — с `-webkit-` дублями. Анимировать только `opacity` и `transform`, до 240 мс. На старых ТВ (`body.lite`) анимаций нет.
- **Плагины**: API версии 1 не ломать. `shared/plugin-runtime.js` — общий для Android WebView и web; изменения в нём обратно совместимы.
- **Обновления**: не ломать `web/boot.js` (обновление без переустановки и откат). Старые ключи `localStorage` (`url`, `epgurl`, `favs`, `auto`, `plugins`) и `Prefs` (`playlist_url`, `epg_url`, `favorites`, …) продолжают работать; новые данные — рядом, с миграцией (SPEC 5.2, 10.2).
- **Не трогать**: `app/release.jks`, подпись, `.github/workflows/*`, версии и релизы, `README.md` (кроме раздела про управление, если поведение кнопок изменилось — в самом конце работы).
- **Ничего выдуманного**: нет родительского контроля, субтитров, звуковых дорожек, смены темы, диагностики сети, статистики потока, истории поиска, сортировки избранного, настроек плагинов, каталога плагинов, паузы прямого эфира. Новые функции — только шесть из SPEC «О документе»: несколько плейлистов, «Недавние», поиск передач, громкость/«Без звука», описание передачи из `<desc>`, сетка «каналы × время», плюс ошибка запуска плагина в карточке. Всё новое помечается меткой «новое» (SPEC 3.10).
- Тексты интерфейса — только из SPEC и макетов, по-русски, без сокращений, которых там нет.

## Порядок работы

Работай в ветке `redesign/tikhiy-efir`. Каждый этап — отдельный коммит (или несколько), сборка и тесты зелёные после каждого этапа.

**Этап 0. Разведка и план.** Прочитай SPEC, `web/app.js`, `web/style.css`, `web/index.html`, `app/src/main/java/com/volnalabs/tv/ui/*.kt`, `data/*.kt`, `shared/plugin-runtime.js`. Составь `docs/design/IMPLEMENTATION_PLAN.md`: для каждого раздела SPEC — какие файлы и функции меняются, что новое, риски. Покажи мне план и дождись подтверждения только если нашёл противоречие, которое нельзя решить по SPEC; иначе продолжай.

**Этап 1. Основа.** Токены (готовыми значениями в `style.css`; `colors.xml`, `dimens.xml`, `styles.xml` на Android), шрифт Onest (web — base64 WOFF внутри `style.css`, чтобы не повышать `SHELL`; Android — `res/font`), иконки (расширить `ICON` в `app.js`; VectorDrawable `ic_*.xml`). Убрать цветные буквенные плашки логотипов (`COLORS`, `LetterDrawable`) → нейтральная плитка. Класс `body.lite` и его определение (SPEC 10.4). Новые подсказки кнопок (SPEC 3.1 «Подсказки кнопок», 8.2).

**Этап 2. Гид ТВ (web + Android TV).** Композиция Lampa: шапка с плейлистом и часами, меню разделов 450 + 56, плитки каналов 340×236 с фокусом на второй позиции, подробности с программой и описанием, строка даты, меню плейлистов, меню действий по удержанию OK (650 мс, существующий механизм `enterTimer`). Таблица переходов — SPEC 8.1; фокус и «Назад» — 8.3.

**Этап 3. Плеер.** Разделить «выбранный» и «играющий» канал: ▲▼ запускают поток через 400 мс после последнего нажатия. OK — панель управления (SPEC 4.2), ◀ — мини-гид, CH LIST — гид. Новый OSD, верхняя строка, метка записи, шкала записи, ввод номера, громкость, все состояния SPEC 4.4 (блок `ip-state` вместо `#msg`), выход двойным «Назад».

**Этап 4. Мини-гид, сетка, поиск.** Мини-гид (SPEC 3.3), сетка «каналы × время» с абсолютной раскладкой и ≤ 40 ячейками (3.4), поиск по разделам с поиском передач и подсветкой совпадений (3.5, 8.7).

**Этап 5. Настройки.** Разделы и элементы SPEC 5.1; несколько плейлистов с миграцией; «новая ссылка заменяет список только после проверки»; состояния формы и тексты ошибок (5.3); «Воспроизведение» только на Android.

**Этап 6. Плагины.** Список с порядком и статусами, «Добавить» в конце, карточка, установка с предупреждением, включение/выключение, «Обновить код» (Android), удаление через диалог + «Вернуть» 6 с, ошибка запуска (`host.error` в рантайме, `lastError`, `hasPlaylist/hasStream` в `list()`). SPEC раздел 6.

**Этап 7. Android Mobile и Tablet.** Телефон вертикально/горизонтально, планшет 600–899 и ≥ 900 dp (SPEC 7.3).

**Этап 8. Desktop.** Режим окна `body.desk` без `fit()`, три колонки, брейкпоинты 1680/1360/1024/640, полный экран с ТВ-видом плеера, мышь и клавиатура (SPEC 7.6, 8.4, 8.5). Это самая крупная часть — делай последней.

**Этап 9. Проверка и отчёт.** Пройди чек-лист SPEC раздел 11 и отметь каждый пункт в `docs/design/QA.md` (пункт → платформа → как проверено → результат). Приложи свои скриншоты рядом с эталонами.

## Как проверять

- Android: `./gradlew :app:assembleDebug :app:testDebugUnitTest`. Обнови `ScreenshotTest`/`UiFlowTest` под новый интерфейс; сценарии — SPEC 1 «Ключевые сценарии».
- Web: `scripts/build-web.sh desktop /tmp/iptv-desktop` и `samsung`, `lg`; `node scripts/bundle-web.js 1.0.0 /tmp/w.json /tmp/base.js`.
- ES5: прогоняй `web/app.js` и `shared/plugin-runtime.js` через парсер с `ecmaVersion: 5` (например, `npx acorn --ecma5 web/app.js`). Ни одной ошибки.
- Запрещённый CSS: `grep -nE "var\(|display:\s*grid|[^-]gap:|backdrop-filter|aspect-ratio|:focus-visible|inset:|position:\s*sticky" web/style.css` — пусто.
- Визуально: открой собранный web в Chromium (Playwright) в окне 1920×1080 с тестовым плейлистом (можно сделать локальный M3U + XMLTV в `tmp/`, не коммитить), пройди сценарии клавишами (стрелки, Enter, Escape, цифры), сделай скриншоты и сравни с `screens/` и `flows/`. Повтори для 1280×720 и окна Desktop 1440×900.
- Производительность: список из 1000 каналов, удержание ▼ — без пропуска нажатий; в DOM колонки не больше видимых строк + 2.
